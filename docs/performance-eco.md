# «Эконом»: представление для рендера — 2026-11-17

Вход в общую архитектуру: [performance.md](performance.md). Цель этого этапа — убрать лишнюю работу без дополнительного упрощения изображения.

## Главная перемена

Раньше GPU-пакеты объединялись по полным PBR-материалам, после чего «Эконом» заменял их на Lambert. Шероховатость, металл и карты рельефа уже не участвовали в изображении, но продолжали разделять пакеты и проверяться на CPU.

Теперь `raster-batches.js` строит для eco собственные Lambert-пакеты по реально используемому состоянию. В измеренной квартире получилось 62 группы вместо 97. `eco-material-state.js` — единый список карт, параметров и фабрика для пакетов и прежних подмен отдельных объектов. Цвет остаётся индивидуальным для каждого экземпляра; свечение, текстуры, отсечение, прозрачность, глубина и остальные используемые параметры сохраняются.

Это отдельное представление только для растрового кадра. Исходные объекты, сетевые ID и геометрия продолжают обслуживать взаимодействия, попадания, физику, GLB и фото. Высокие качества используют полную PBR-эквивалентность. Пока пакет не готов, работают исходные объекты и прежний eco-путь; несовместимые PBR-материалы никогда не рисуются объединённым PBR-заменителем.

## Остальные изменения и защитные условия

- Неизменившиеся описания геометрии переиспользуются при сканировании. Проверки реальных изменений сохранены; индекс, массивы и формат атрибутов входят в ключ перестройки. Исправлен случай старых треугольников после замены индекса с прежним `version`.
- Поиск eco-материалов использует общий `scene-index`, сохраняя подготовку невидимых объектов, проверку предков и период 350 мс.
- Лучи дверей, сидений, вытяжки и проверок видимости TV/монитора/живого дома запрашивают ближайшую поверхность каждого меша. Лучи оружия и выбора материалов не изменены: закреплённая BVH 0.7.8 имеет особенность `face.materialIndex` в nearest-only режиме.
- Прогрев может быть прерван другим вариантом программы, например при подготовке GI. Повтор идёт через 250 мс, максимум четыре неудачные попытки; затем сохраняется исходный рендер. Изменение материала, представления или восстановление контекста разрешает новую подготовку. Удалённый пакет не воскресает из старого Promise.

## Замеры

Chrome 157, Apple M5 Pro, 1280×720, eco. Сравнение фиксированного `7451053b95cd18bb8e8fe9ebdf96db9a857a9454` с теми же JS/spec плюс точными performance-правками; параллельные новые фичи в сравнение не включены. CPU DevTools ×4 включён после полной подготовки, GPU не замедлен. Каждый ракурс измерялся четыре секунды с непрерывным запросом реальных кадров.

Это наблюдения одного парного прогона, не гарантия на другом устройстве. Живые события и нагрузка машины меняются. Эмуляция CPU не заменяет физический слабый телефон, его GPU, Safari или Firefox. В режиме CPU ×4 цель 60 FPS пока не достигнута.

Без замедления CPU итоговый solo/host/guest-прогон держал около 60 FPS, оба клиента сохранили соединение после fast/high/eco, PNG и мобильной ширины. Шесть мобильных проверок подтвердили поворот, готовность оружия, выстрел/расход патрона и вспышку у наблюдателя, перезарядку и повторный вход без ошибок.

У гостя с CPU ×6 измерено 9,56 → 12,51 FPS, CPU растрового кадра 70,3 → 51,7 мс. Но контроль потерял игрока при последующем smoke, а итоговая версия — после дополнительного тяжёлого сценария качества/PNG. Это не пройденная полная проверка мультиплеера на слабом устройстве; проблема соединения не объявляется исправленной.

## Проверка и воспроизведение

Изолированный релизный набор: 182 теста `npm test` и `npm run build` прошли; независимое ревью геометрии, переключений качества и отказов компиляции. В общем checkout прошли 209 тестов и сборка, но он дополнительно содержит работу другой сессии: её файлы не входят в performance-коммит.

`tools/qa/raster-representation-qa.mjs` сравнивает пиксели двух путей в одном настоящем WebGL-контексте: 24 объекта / 12 PBR-материалов превращаются в одну eco-группу; высокое качество — в 12 PBR-групп. На eco совпали все 614400 каналов; на high один канал отличается на 1/255. Оригинальные материалы сохранены. Это точная проверка ограниченной сцены; полная квартира отдельно просмотрена в браузере.

`tools/qa/performance-qa.mjs`: обычный запуск — solo/host/guest; `QA_ROOMS=1` — девять ракурсов и настоящий выстрел/ходьба. `QA_ROOM=bath-mirror` или список через запятую ограничивает маршрут. `QA_CPU_RATE`, `QA_HOST_CPU_RATE`, `QA_GUEST_CPU_RATE` задают замедление; `QA_EXTENDED=1` добавляет качества, PNG и мобильную ширину; `QA_NO_MULTIDRAW=1` проверяет fallback браузера. `PLAYWRIGHT_MODULE` указывает существующий Playwright, `QA_URL` — проверяемую сборку, `QA_OUTPUT` — отдельную временную папку.

Подробные локальные receipts и границы проверки: `output/playwright/performance-eco-2026-11-17/README.md`. Скриншоты после просмотра удаляются. Каждый harness ограничен по времени и закрывает свой браузер в `finally`.

Следующий потенциальный архитектурный этап — разделение изменений камеры, динамических объектов и статического мира, чтобы убрать проверки неизменившихся стен из каждого кадра. Он требует явного учёта всех прямых изменений сцены: редактора мебели, загрузки моделей/текстур, роста декора, разрушений, дверей и сетевых восстановлений. В этом релизе такой контракт не вводился: параллельные фичи продолжают пользоваться прежними правилами изменения мира.
