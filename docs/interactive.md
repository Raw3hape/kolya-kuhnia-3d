# Напитки, передача вещей и радиомашинки

Вход: [README](../README.md). Подсистемы: [напитки](drinks.md),
[машинки](rc.md), [независимая проверка](multiplayer/qa-independent-interactive.md).

## Пользовательский путь

- Крайний нижний кухонный модуль — холодильник: наведите и нажмите E.
  Её тонкая дверца не сужает пеший проход; корпус остаётся препятствием.
  Внутри 36 бутылок, шесть вымышленных вкусов с русскими польскими шутками.
  Взять E, один глоток ЛКМ, всего пять; можно пить на любом сиденье.
  Пустой энергетик сжать C, бросить Q. На телефоне действия подписаны.
- Пиво на балконе можно бросать. Бутылка разбивается, осколки остаются.
  Состояние мусора сохраняется до явной очистки сцены в текущей игре;
  поздний участник комнаты получает то же состояние.
- Подойдите к другу со свободными руками: кнопка «Передать · имя» или H.
  Передаются телефон, газета, напитки, пицца, пульт и другие вещи,
  зарегистрированные в общем владении. Кальян учитывает длину шланга.
- На отдельном столике слева на балконе — десять пультов. E / «Взять пульт»
  включает машинку и камеру следования. W/S газ/назад, A/D руль,
  Пробел тормоз. Кнопка «Закончить гонку» / Esc возвращает к персонажу.
  Мышь / тачпад: тянуть по сцене для обзора, колесо / два пальца — масштаб;
  C / «Камера за машинкой» возвращает обзор. На телефоне отдельные кнопки
  газа, руля и тормоза; обзор пальцем и масштаб щипком работают одновременно с газом. R возвращает
  застрявшую машинку без восстановления HP; после уничтожения нужен ремонт.

## Контракты для продолжения

Общие чистые симуляции `party-state.js`, `social-state.js`, `rc-state.js`
работают и в соло, и в Worker хоста. Three.js-модули только отображают
состояние и передают намерения. Параметры, модели и позиции задаются
`spec/party.json`, `spec/kitchen.json`, `spec/rc.json`.

`multiplayer/authority.js` подтверждает `handoff {id,targetId}` одной
транзакцией: связанный получатель, свободные руки, дистанция, препятствия,
истинный владелец, ограничения текущего действия. Специализированные
семейства предоставляют `transfer(from,to,id,players)`. Обычные вещи
используют общий реестр `items`; новый экран передачи не нужен.

Соло использует `carry-coordinator.js`: новый тип предмета регистрирует только
`held` и `release`, без списков других подсистем. Перед освобождением рук чистые
`canTake` проверяют, что новая вещь действительно доступна; смена поколения
сессии отменяет устаревшие захваты после ожидания.

RC-команды: `rc {verb,id,input}`; ввод `{seq,throttle,steer,brake}`.
Хост никогда не принимает клиентские координаты машин, HP или урон.
Выстрелы проходят общий порядок препятствий/животных/машин. Контроллер
блокирует движение тела и прыжок на клиенте и в authority. Передача,
потеря связи и выход сбрасывают моторный ввод. Транспорт и лимит десяти
игроков остаются общими с квартирой; версия протокола 6.

`render-view-camera.js` временно подставляет камеру гонки только на
синхронную отрисовку. Поза персонажа, взаимодействия и сеть используют
его исходную камеру. Камера гонки сохраняет горизонт при крене машины.

## Проверка

`npm test`, `npm run build`; браузерный сценарий:

```sh
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tools/qa/interactive-qa.mjs
```

`QA_URL`, `QA_OUTPUT`, `QA_SOLO_ONLY=1`, `QA_RC_ONLY=1`, `QA_ROOM_ONLY=1` позволяют выбрать
окружение и ограничить повторную проверку. У сценария есть timeout,
`finally` закрывает все свои браузерные контексты и процесс. Скриншоты
в `output/playwright/` временные, в Git не входят. Итоговые фактические
результаты и границы доказательства — в [QA](interactive-validation.md).
