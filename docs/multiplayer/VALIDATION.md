# Проверка мультиплеера · 2026-11-16

Источники и ограничения: [ARCHITECTURE.md](ARCHITECTURE.md). Игровые API: [GAMEPLAY.md](GAMEPLAY.md).
Три агента отдельно исследовали архитектуру, реализовали подсистемы и проверяли права/UX/состояния.

## Автоматическая проверка

`npm test`: 34 проверки прошли, включая попытку удалённого участника занять внутренний ID хозяина.
Покрыты 10 мест/отказ 11-му, подпись хозяина, роли, reconnect/закрытие, стены и тела,
предметы/сиденья, единственный зачёт убийства, плоские поверхности, зависимые разрушения,
все варианты отдельных вещей, устойчивые ID, кодек/база/журнал, видео/газета/вытяжка.

`node tools/vendor_three.mjs --check`: 29 файлов Three.js, 2 056 160 байт, SHA-256 и импорты проверены.
`npm run build`: 763 папки ассетов, 136 texture meta, 44 модуля + 20 спецификаций preload,
52 JS сжаты. Design Director gate: 0 P0, 0 P1.

## Настоящий браузер

Chromium 157, временные контексты, обычный PeerJS Cloud и native RTCDataChannel без mock:

- Полная 3D-квартира хозяина + 9 сетевых участников: 10 подключены, персонажи различаются,
  состав и состояние совпадают. 11-й получает сообщение о полной комнате.
- Два полных 3D-клиента: гость не меняет квартиру через UI/debug API или сетевую команду.
  Попытка пройти сквозь игрока останавливается на расстоянии 0,44 м между центрами.
- Настоящими кликами разбиты книга, керамика, окно; у обоих одинаковые ID повреждений/боезапас.
  Два запроса телефона дают один успех; чужое управление телефоном отклоняется, возврат освобождает его.
- Хозяин меняет время: гость получает то же значение. Вытяжка и выбранные видео совпадают.
  Сидение и вставание публикуют/освобождают место. Esc гостя открывает участников.
- Точное scripted aim прошло через реальный host raycast и Worker: кабан умер, одно начисление
  185 очков совпало на втором клиенте. Нативный промах остался промахом.
- Свежий мобильный гость 390×844 получил уже разбитые книгу/керамику/стекло; нет JS-ошибок и overflow.
- В ванную прошли клавишами с обходом открытого полотна: газета взята, ArrowDown листает общую
  страницу, Q возвращает следующий выпуск. Разбитое зеркало, 2 дырки, выпуск и вытяжка восстановлены у нового гостя.
- Журнал у клиента: 2 события/2 дырки → последнее/1 дырка → повтор без изменений → полная база/2 дырки.
- Галерея `/characters.html`: 10 реальных моделей, один renderer, нет постоянного RAF.
  Desktop/mobile вход, подписи и галерея визуально проверены.

## Производительность и границы

Один 3D-хозяин + 9 настоящих WebRTC-клиентов без собственных рендереров: 120 кадров,
p50 16,7 мс / p95 16,8 мс, около 60 FPS. Это не тест десяти отдельных устройств.
При двух полных сценах на одном Mac: p50 33,4 мс / p95 50,1 мс.
384 меша ускорены BVH; 60 точных лучей: среднее 0,89 мс / p95 1,30 мс.
Насыщенный fixture кодека: примерно 391 КБ → 1,98 КБ/кадр; 20 Гц × 9 гостей ≈2,85 Мбит/с payload.

Произвольные пары интернет-сетей и отдельные физические телефоны не проверялись.
Без TURN строгий NAT/firewall может блокировать соединение; ОС может приостановить хозяина в фоне.
Хозяин держит вкладку открытой. Абсолютная безотказность не заявляется.
