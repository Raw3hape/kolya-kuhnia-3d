# Обстановка комнат (реальные вещи)

Код: `web/js/decor.js`. Каталог: `web/spec/decor/index.json` → `web/spec/decor/<zone>.json`.
Модели: `web/models/decor/<zone>/<id>/` (`model.glb`, `thumb.jpg`, `SOURCE.md`), общий реквизит (книги, растения,
вазы, рамки) — `web/models/decor/props/<id>/`: существующую папку не перезаписывать, только переиспользовать.
Конвейер: `tools/decor/` (ниже).

## Код варианта: только дописывать

Каждый слот — поле `d_<zone>_<slot>` в коде ссылки `#v3-…`, значение — номер опции в слоте.
Порядок полей: зоны в порядке `index.json`, слоты в порядке файла зоны. Поэтому:

- новые зоны — в конец `index.json`, новые опции — в конец слота;
- новый слот — в конец файла зоны **только у последней зоны** `index.json` (сейчас `balcony.json`). Слот в конце
  любой другой зоны встаёт в середину кода и сдвигает поля всех зон после неё — старые ссылки прочитаются
  неверно. Вещь для не последней зоны — новой опцией существующего слота или новой зоной в конце `index.json`;
- ничего не переставлять, не удалять и не переименовывать (`id` зоны, слота и опции);
- файл зоны из `index.json` всегда должен существовать и быть валидным JSON: пропавшая зона сдвигает поля
  всех зон после неё. Битый файл приложение переживёт (зоны просто не будет), но ссылки, сделанные
  в это время, потом прочитаются неверно;
- обстановка — последний блок `SCHEMA_V3` в `main.js`; новые поля самого main.js туда после неё дописывать нельзя.
  Новое поле сцены (не вещь) — «слот-поле» в конце последней зоны: `{ "id": "season", "field": "balconySeason" }`.
  Оно только держит место в коде: в коде ссылки это поле `state.<field>` (не `d_…`), варианты и значение по
  умолчанию — `FIELDS` в `decor.js` (у `hallGlow` — `LAMP_OPTIONS` в `lamps.js`). В обстановку, `decorKey` и
  список слотов панели оно не входит; неизвестное `field` всё равно занимает своё место. Сейчас в конце
  `balcony.json` два таких поля: `balconySeason` (сезон балкона) и `hallGlow` (подсветка прихожей).
  `tools/decor/balcony/compose.py` дописывает их сам — правки руками в `balcony.json` перезапишутся.

## Файл зоны

```json
{ "zone": "room2", "title": "Спальня", "room": "room2",
  "slots": [
    { "id": "bed", "label": "Кровать", "default": "malm-160",
      "options": [
        { "id": "none", "name": "Нет" },
        { "id": "malm-160", "name": "MALM rama łóżka 160x200", "brand": "IKEA", "article": "000.000.00",
          "url": "https://www.ikea.com/pl/pl/p/…", "price_pln": 899, "finish": "biały", "note": "…",
          "size": [1.76, 1.0, 2.09], "thumb": "models/decor/room2/malm-160/thumb.jpg", "collide": true,
          "seat": { "h": 0.45, "depth": 0.3, "label": "Сесть на кровать" },
          "parts": [ { "model": "models/decor/room2/malm-160/model.glb", "pos": [4.1, 0, 5.8], "rot": 180 } ] }
      ] } ] }
```

- Первая опция слота — всегда `{ "id": "none", "name": "Нет" }`. `default` — опция по умолчанию
  (нет или опечатка — «Нет»).
- `pos` — центр следа в координатах квартиры (X вдоль окон, Z вглубь, метры; комнаты и проёмы —
  `web/spec/plan.generated.json`), `y` — высота основания: 0 — на полу, > 0 — на стене.
- `rot` — градусы вокруг +Y, 0 = перед смотрит в +Z; 90 — в +X, −90 — в −X, 180 — в −Z.
- `size` — Ш × В × Г всей опции вокруг первой части, метры: карточка в панели и проверки проходов.
- `collide` — мешает ли пройти (прогулка F). По умолчанию да: сталкивается каждая часть, стоящая на полу
  (`y` < 0,3), по габариту своей модели; плоское (ковёр, ниже 15 см) и настенное не мешают. `false` — опция проходима.
- `parts` — одна опция может собирать несколько моделей (полка + книги + растение, две вешалки).
- `on` (необязательно, на части) — id слота той же зоны, на вещи из которого стоит часть (лампа на тумбочке):
  если в том слоте «Нет», часть не строится.
- `seat` (необязательно, на опции или на части) — на этом можно сесть в прогулке (`seats.js`):
  `h` — высота сиденья, `depth` — сдвиг от центра следа назад к спинке, `label` — подсказка.
  Направление взгляда — из `rot` части. Опция-уровень относится к первой части.
  `buildDecor(...).seats` отдаёт `[{ id, label, x, y, z, yaw }]` в координатах квартиры (yaw — радианы, 0 = +Z).
- `name` — точное польское название из магазина, `price_pln` — цена в zł на дату съёмки (в `SOURCE.md`),
  `article` — артикул как на сайте. В панели: миниатюра, имя, бренд, размер, цена, ссылка; `finish`,
  `article` и `note` — во всплывающей подсказке. Ничего не выдумывать: только реальные товары.
- `anchor` (необязательно, на части) — `"console"` | `"tv"` | `"island"` | `"table"` | `"sofa"`: часть стоит на
  этой вещи или при ней. `pos`/`rot` пишутся для положения вещи по умолчанию; сдвинули вещь (ползунки, редактор,
  остров — ползунками кухни, тумба — сменой типа: высота крышки и передняя кромка) — часть едет следом.
  Вещи нет («Нет» у тумбы/ТВ) — часть скрыта. У ТВ и тумбы часть, вылезшая бы за конец стены, скрыта.
- `mount` (необязательно, на части) — `"floor"` | `"wall"` | `"surface"`: как часть двигается в редакторе.
  Без поля: `y` < 2 см — пол; на другой части или с `anchor` — поверхность; иначе решает луч вниз при выборе
  (опора ближе 4 см — поверхность, нет — стена).
- `season` (необязательно, на части) — `"summer"` | `"winter"`: часть видна только в этот сезон сцены,
  `sceneSeason(state)`: «Сезон» балкона (`state.balconySeason`) — «Лето» / «Зима», а «По дате» (`auto`, по
  умолчанию) — `decorSeason(state.sunDate)`: ноябрь–март — зима, апрель–октябрь — лето. Панель балкона
  показывает, во что «По дате» сейчас превращается. Модели обоих сезонов грузятся при
  сборке; смена даты или «Сезона» только прячет и показывает части в `placeDecor` (его зовёт `setState`) — без пересборки,
  загрузок и новых шейдеров. Спрятанная часть не сталкивается и не даёт места; `decorKey` сезон не включает,
  сдвиги и носители работают как обычно. Миниатюра опции — летний состав.
- Клик по вещи в 3D открывает её слот в панели. Убрать или заменить — опцией; пересобирается обстановка только
  при смене этих полей.

## Перестановка (редактор «Двигать мебель»)

- Двигается каждая часть каждой опции отдельно: пол — по полу (стены держат), стена — вдоль своей стены
  (до проёма или угла, по высоте от пола до потолка), поверхность — по поверхности; отпустили над другой
  вещью или полкой — встаёт на неё (луч вниз), Shift — без шага 1 см. Поворот — ручкой или клавишами.
- Носители находятся сами после загрузки моделей: часть, чьё основание лежит внутри габарита другой части
  той же опции (или слота из `on`) в положении по умолчанию, едет вместе с ней (книги в стеллаже, лампа на тумбочке).
- Места (`seats`) и столкновения пересчитываются по новым положениям; геометрия не пересобирается.
- Сдвиги хранятся в `state.moves` и в ссылке хвостом после `~`: `#v3-…~<запись>~<запись>`. Запись =
  `<zone>.<slot>.<option>.<номер части>_<dx>_<dz>_<dy>_<dr>_<on>` (мм и градусы, целые base36 со знаком,
  нули в конце отброшены; `on` — новый носитель: pkey части, id опоры или `0` — свободно). Сдвиг задан
  относительно носителя/опоры в положении по умолчанию. Записи о пропавших опциях игнорируются; ссылки без `~`
  открываются как раньше. «На место» — у выбранной вещи, «Всё на место» — для всех.
- Поэтому `id` зоны, слота, опции и порядок `parts` не менять: на них держатся сдвиги в сохранённых ссылках.

## Контракт GLB

Как у диванов (`web/models/sofas/README.md`): метры, пол Y = 0, центр следа в 0, перед в +Z (оси glTF),
реальные габариты, meshopt (`KHR_mesh_quantization`, в three нужен `setMeshoptDecoder`), обычно ≤ 1,5 МБ,
текстуры ≤ 1024. Рядом `thumb.jpg` 256 × 256 и `SOURCE.md`: ссылка на товар, бренд, артикул, цена PLN,
дата съёмки, лицензия, масштаб. Модели IKEA без публичной лицензии — только личная визуализация.

## Конвейер (tools/decor/)

1. `python3 tools/decor/fetch_ikea.py search "<запрос>"` — товары ikea.com/pl: артикул, имя, размер, цена, ссылка.
2. `IKEA_CLIENT_ID=… python3 tools/decor/fetch_ikea.py info <артикул>…` — есть ли 3D и размеры IKEA.
   Ключ — заголовок `X-Client-Id` запроса `web-api.ikea.com/…/rotera/data/model/` со страницы товара
   (вкладка Network); в репозиторий не кладётся.
3. `blender -b --python tools/decor/inspect.py -- raw.glb` — габариты сырого файла. Настенные модели IKEA
   (зеркала, полки, вешалки) лежат «стеной вниз»: им нужен `"rot": [90, 0, 0]`.
4. Записи в `tools/decor/jobs/<zone>.json` (`id`, `zone`, `article`, `rot`, `maxTris`), затем
   `IKEA_CLIENT_ID=… python3 tools/decor/pipeline.py tools/decor/jobs/<zone>.json <tmp> [id…]` — скачивает,
   нормализует (`normalize.py`), сжимает meshopt и рисует `thumb.jpg` (`thumb.py`). `<tmp>` потом удалить.
5. Проверить ориентацию по миниатюре (перед +Z, верх вверху), дописать `SOURCE.md` и опцию в файл зоны.

## Прихожая (hall)

Вход открывается внутрь, петли слева: левая стена у двери свободна (полотно и его дуга), вещи левой стены
кончаются на z 5,45. Правая стена тамбура — обувница и полка над ней, угол у двери — растение, стена коридора
справа от двери комнаты 3 — зеркало. Проход в тамбуре ≥ 1,2 м, в коридоре только зеркало (2–5 см).

Поле `glow` (необязательно, на опции зеркала и обувницы) — к вещи привязана подсветка прихожей (`lamps.js`,
`state.hallGlow`): `"halo"` — ореол на стене по бокам зеркала, `"under"` — свет под обувницей на пол.
Объект `{ "kind": "halo", "len": 0.6 }` — полоса короче высоты зеркала (доля, для овальных и круглых);
`{ "kind": "under", "y": 0.1 }` — высота дна обувницы над полом (по умолчанию 0,08 м).
Свет берётся из `pos`/`size` первой части; сдвинутую в редакторе вещь подсветка не догоняет — гаснет.
Источники строятся для всех опций сразу (шейдерные полосы), выбор только гасит лишние.

## Кухня (kitchen)

Каталог генерирует `tools/decor/kitchen/compose.py` (раскладки там, не в JSON); модели — `build.py` → `pack.py`,
SOURCE.md — `sources.py`, источники и цены — `tools/decor/kitchen/products.json`. Полки и рейлинг — стена X = 0
(низ ниже 1,5 м — на лице фартука 12 мм), картины — грань шахты X 0,6013 и стена у окна, вещи острова и стулья —
`"anchor": "island"`. Миниатюры опций — `web/models/decor/kitchen/thumbs/<слот>-<опция>.jpg`.

## Балкон (balcony)

Каталог генерирует `tools/decor/balcony/compose.py` (раскладки и миниатюры опций там, не в JSON); модели —
`fetch.py` → `make_tex.py` → `build.py` → `pack.py`, SOURCE.md — `sources.py`, товары и цены —
`tools/decor/balcony/products.json` (порядок шагов — шапка `build.py`). Всё стоит одной полосой у фасада
(глубина ≤ 0,76 м, крона бамбука в левом углу — 0,9 м): вдоль перил сквозной проход ≥ 1,08 м (в углу 0,93), у перил ничего выше поручня — поле для охоты (hunt.js)
видно на высоте глаз. Перед дверью комнаты 3 (x −1,68…−0,48) и открывающейся створкой гостиной (x ≥ 4,45) пусто:
проход и место у перил 1,2 м. Мебель стоит на плите (y −0,02), настил RUNNEN 2 см поднимает пол вровень с
квартирой. Сезонный текстиль, зелень и фонари — части с `season` (летом подушки и лаванда, зимой шкуры, плед,
ёлки и фонари у доницы). Миниатюры опций — `web/models/decor/balcony/thumbs/<слот>-<опция>.jpg`.
